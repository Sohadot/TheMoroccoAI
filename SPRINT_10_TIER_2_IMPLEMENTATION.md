# Sprint 10 Tier 2: Public Reference Surface (v0.10.1)

## Why a separate file

`SPRINT_10_TIER_0_ASSESSMENT.md` is the approved reference-model design, with the owner's decisions and the Tier 1 record of the machine-readable contract. Tier 2 is a different kind of deliverable: a presentation layer over that contract, with its own boundaries and tests. Appending it would turn a design document into a running log. A separate file keeps each record to one purpose and leaves the design as approved. No historical assessment was rewritten.

## Architecture

```
canonical data → reference-state.json (Tier 1, governed) → /registry/state/ (Tier 2, presentation)
```

- **Generation.** The page is generated by `tools/build.py` (`render_state`). It is static HTML in the existing design system, with no runtime JavaScript, no framework, no charting library and no third-party request. JSON-LD (a `Dataset` pointing at `/registry/reference-state.json`), the canonical URL, Open Graph metadata and the sitemap entry come from the existing page template.
- **Semantic source of truth.** Every governed value is read from the parsed snapshot: counts, members, groups, lifecycle stages, project kinds, status bases, AI-deployment flags, target-to-gap mappings, gap states, GAP-07 dimensions, unresolved lists, superseded records and relationship lists. The renderer does not rerun any Tier 1 query.
- **Presentation-only canonical lookups.** These come from `evidence.json`, `ontology.json` and `gaps.json`:
  - entity names;
  - record titles;
  - gap questions;
  - classification definitions;
  - predicate labels;
  - the display order of GAP-07's dimensions;
  - vocabulary order for listing counts.

  Each lookup is marked `data-label="kind:key"` and may only label a key already present in the snapshot. A lookup never decides membership, grouping, lifecycle or classification.

### How fidelity is enforced

- **Marking.** Each governed value is wrapped with `data-ref` (a JSON pointer into the snapshot; `#count` after a list's pointer means its length) and `data-value` (the snapshot value as JSON).
- **Build gate.** `state_page_errors` runs on every build, and the build refuses to write the page when it finds any of the following:
  - a `data-ref` that does not resolve, or whose `data-value` differs from the snapshot;
  - a count whose displayed text differs from its value;
  - a snapshot value (outside `derivation`) that is not shown;
  - a `data-label` naming something absent from the snapshot, or not matching the canonical data;
  - static text (everything outside `data-ref` and `data-label`) that contains a digit, which would be a number not read from the snapshot;
  - static wording that carries a judgment the snapshot does not encode: scores, confidence, completeness, maturity, readiness, rankings, "top"/"leading", progress, "on track", achievement, targets met, cumulative sums, funders, government or regulatory actors, first-party classifications, "adopted", "in use", "widely", "not delivered", "failed", conflicts, disagreement, "evidence state", "quality";
  - a missing required boundary statement;
  - a `details` element without a `summary`.

  The seven boundary statements are the only static sentences allowed to name an excluded concept ("Conflicting official statements are not resolved by inference").

## Forbidden semantics (not present, refused by the build)

No section or wording for:
- AI or strategy progress, target achievement, or targets met / not met;
- conflicts or conflict counts, or "where official sources disagree";
- AI maturity or readiness;
- confidence or completeness scores, or an aggregate evidence state;
- top or leading organisations, funding leaders, government or regulatory actors, or ecosystem rankings;
- cumulative appropriations;
- derived OSI ranks;
- first-party classification.

No prose from notes or gaps is parsed. Gap questions appear only as quoted labels.

## Limitations

- **Covering gap.** `official_targets[].initiatives[].covering_gap` keeps its deterministic file-order selection. If a targeted initiative is later covered by more than one gap, file-order selection would require semantic governance before v1.0. Today each targeted initiative is in exactly one gap. This is technical documentation, not page content.
- **Canonical labels.** The forbidden-wording gate applies to the page's own static text. Quoted canonical labels (record titles, gap questions) and governed snapshot values are excluded, because they are the data's own words. For example, GAP-01's question mentions "adoption" and MAI-EV-0062's title mentions a "ranking objective". Lookups are still checked to match the canonical data exactly.
- **Open gaps count.** It is shown as the length of `open_gaps` (`#count`), not as a field of `counts`, which has none. Every list length shown on the page is marked the same way and checked.
- **Display order** of counts follows the vocabularies' order in the canonical files, which is a presentation choice. GAP-07's dimensions follow `entity_assessment.dimension_order`, as on the gap register.
- **Conflicts and progress** remain ungoverned. The page points to gap and evidence pages, where the prose lives, and counts nothing.
